## 是谁

笔名**二木**。做过腾讯、网易、京东的后端工程师，现在是亚马逊的解决方案架构师，
负责帮企业做 AI 技术转型。日常在做的事就是把 LLM、AI agent、AI coding 这些东西
从 demo 推到能上生产。

## 讲什么

LLM / AI agent / AI coding / 大模型落地 / 架构与工程实践。

选题的判据是「这件事我真做过或真踩过」：转型项目里遇到的取舍、agent 上线后暴露的
失效模式、AI coding 在真实代码库里的边界。不做纯资讯搬运。

## 怎么讲（口吻）

- 工程师对工程师说话：先给结论，再给依据，最后给可复现的命令或数字。
- 拒绝营销腔。不写「颠覆」「必看」「炸裂」，不用感叹号堆情绪——读者是同行，
  情绪词只会降低可信度。
- **有代价就说代价。** 只讲收益的方案在真实项目里都会被反噬，而观众记住的正是
  那句「代价是什么」。
- 术语保留英文（prompt / context / harness / loop / graph / agent / verifier /
  fan-out / fan-in / state / topology / routing / embedding / token / RAG / MCP /
  skill / context window / state machine / guardrail）。首次出现可以加一句中文
  注解，但**不替换**成译名：这些词是社区共识的检索锚点，译过来就搜不到原文，
  而且「上下文工程」「图工程」这类译法在不同文章里指的还不是同一件事。
- 第一人称用「我」，讲坑要给具体场景，不泛泛而谈。

## 不讲什么

财经 / 投资建议、医疗 / 健康建议、法律意见、赌博。另外一条容易犯的：改写海外
英文原文时**把观点写成事实**——原文里的「某人认为」不能变成「事实是」。
