# CLI 参考

`vagent` = `bun run src/cli/main.ts`（package.json script）。在仓库目录下运行。

```bash
bun run vagent <命令> [参数]
bun run vagent help          # 命令表 + 停点提示
```

## 契约

- **stdout = 结果，stderr = 进度/诊断。** 管道取结果时只需要 stdout。
- `--json` 时 stdout 只输出单行 `JsonEnvelope`：`{ok, step?, data?, error?}`，
  stderr 仍是进度诊断。
- `src/cli/main.ts` 是全项目**唯一**的 `process.exit` 调用点；core 模块只抛
  类型化错误，从不退出进程。

## 怎么读这份文档

**命令参考是生成的。** 下面「命令参考」整段由 `bun run docs:cli` 从
`src/cli/parse.ts` 的路由表生成，`bun run check` 里有漂移门禁——加了参数不重新生成
会当场失败。要查参数就看那一段，或者直接让程序读：

```bash
bun run vagent schema --json
```

标记块之外都是手写的设计取舍，那部分只有人能写。

## 设计取舍（手写）

- **零 CLI 框架。** `util.parseArgs` + 一张路由表，没有 commander/yargs。参数元数据
  因此是我们自己的数据结构，`--help`、`schema --json`、`docs/cli.md` 三处输出同一份
  事实源；换成框架就要迁就它的元数据模型。
- **参数说明是硬门禁，不是文档习惯。** 路由表里每个 flag 必须有 `desc`、枚举必须给
  `values`、每条命令必须声明 `produces`，缺一项测试就失败（`src/cli/parse.test.ts`）。
  这条 CLI 的主要调用方是大模型，它只能读 schema——说明腐烂的代价是它猜错值域、白跑
  一次渲染。
- **`--dry-run` 是全局档，不是逐命令特性。** 分流点只有一个（`main.ts` 的 dispatch
  顶部），所以"零写入"这条保证只有一处需要成立。每条命令各自实现的话，漏一条就是一次
  意外落盘。
- **默认路径从文章名/slug 派生，不用固定常量。** 两条视频并行渲染时，固定的帧目录会
  互相 `rm -rf`（实测丢过 3804 帧，而日志显示「成功」，只有 ffmpeg 报了
  `No such file or directory`）。
- **退出码是锁定表**（`src/core/errors/index.ts`），改动需先协调：skills 和自动化脚本
  按码分支。
- **体裁自动判定按实测配音时长**，不按字数估算：同样字数，播报腔和快语速能差出小一半
  时长，跨过 3 分钟这条线就会选错版式。

#### `tts run`

```
vagent tts run <slug> [--backend <edge|say|minimax>] [--voice <voice>] [--fresh]
```

逐段语音合成并合并音轨（U2）（代价：贵，先 --dry-run）

**前置**：`script validate`

| 位置参数 | 说明                                         |
| -------- | -------------------------------------------- |
| `<slug>` | init 时用的工作目录名（例：`graph-vs-loop`） |

| 参数        | 值域                   | 必填 | 默认                                                                       | 说明                                                                                                                   |
| ----------- | ---------------------- | ---- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `--backend` | edge \| say \| minimax | 否   | $TTS_BACKEND，未设则 edge（收费后端永远不会被隐式选中）                    | 语音合成后端：edge=免费联网 Edge TTS，say=macOS 离线，minimax=收费云端（定稿后换成品音色时才用，需要 MINIMAX_API_KEY） |

| `--fresh`   | 开关                   | 否   | —                                                                          | 先清空 audio/（分段 + 合并音轨 + durations.json）再全量重合成；换后端或换音色时必须给，否则已存在的段不会被重合成      |

**产物**：

- `videos/<slug>/audio/seg-NN.mp3`
- `videos/<slug>/audio/merged.m4a`
- `videos/<slug>/audio/durations.json`

- 逐段幂等：已存在的 seg-NN.mp3 会跳过，中断后重跑只补缺的段

- 只有网络类错误重试（500ms→1000ms），其余立即失败并带后端与段号

- 默认用免费后端（edge）出草稿；minimax 按字符计费，建议只在定稿后跑一次：vagent tts run <slug> --backend minimax --fresh

- 片头封面默认开：主视觉取第一个带图形块的段，文章里可用 > cover: <段号> 指定、> subtitle: 与 > tagline: 配文案

- 成片总时长 = 封面定格 + 正片；SRT 时间戳已跟着后移
