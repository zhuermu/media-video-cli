# 白板手绘动画

一支笔在白板上按真笔顺写字、描线稿图标、描图表、拉入图片，段间运镜，收尾
zoom-out 全览。技术栈：Bun + resvg 逐帧纯函数 SVG + FFmpeg。

有**两条独立入口**，用途不同：

| 入口                     | 输入                         | 谁定画面                   | 适合           |
| ------------------------ | ---------------------------- | -------------------------- | -------------- |
| `compose run`（`style`） | `script.json` + 每段 `scene` | LLM/人显式声明场景元素     | 精确控版的短片 |
| `whiteboard render`      | 一篇 Markdown 文章           | 由 Markdown 结构确定性映射 | 文章直出讲解片 |

---

## 入口一：script.json 场景 DSL

在 `script.json` 根级加 `"style": "whiteboard"`（可选
`"theme": "clean" | "ocean" | "forest"`），且**每段必须带 `scene`**：

```json
{
  "style": "whiteboard",
  "theme": "clean",
  "segments": [
    {
      "text": "口播文字……",
      "cardText": "要点",
      "scene": {
        "elements": [
          { "type": "title", "text": "开场标题", "underline": true },
          { "type": "text", "text": "补充一句" }
        ]
      }
    }
  ]
}
```

场景元素表（每段 1-6 个元素，竖排自动版式，语义声明零坐标）：

| type      | 字段                                             | 表现                                      |
| --------- | ------------------------------------------------ | ----------------------------------------- |
| `title`   | `text`（≤12 字）, `underline?`                   | 大字手写 + 可选强调下划线                 |
| `text`    | `text`（≤18 字）                                 | 正文手写行                                |
| `bullet`  | `text`（≤18 字）                                 | 对勾 + 手写要点行                         |
| `icon`    | `name`, `accent?`, `label?`（≤10 字）            | 线稿图标笔描                              |
| `chart`   | `chart: "bars-up"\|"line-up"\|"steps"`, `label?` | 图表笔描 + 填色淡入                       |
| `image`   | `src`(.jpg/.jpeg/.png), `circle?`, `label?`      | 照片拉入（路径同 `backgroundImage` 约定） |
| `sticker` | `name`                                           | 色块装饰件（淡入，不占版式）              |

`icon` 可用名：`arrow-right` `arrow-swoosh` `circle` `check` `cross` `star`
`burst` `wave` `lightbulb` `box` `speech-bubble` `cloud` `magnifier` `heart`
`target` `rocket` `trophy` `thumbs-up` `crown` `fire` `sparkles` `flag` `pin`

`sticker` 可用名：`blob` `tape` `star-badge` `confetti` `highlight`

未知的 `icon`/`sticker` 名、超长文案、坏 `chart` 种类会在 `script validate`
阶段**一次报全**并列出可用清单。

**写作建议**：每段 2-3 个元素为宜（口播 15-25 秒才撑得起 4 个以上）；开场段用
`title`；图表/图标段配 `label`；全片至多 1-2 个 `sticker` 点缀。

`image.src` 的相对路径解析到 `videos/<slug>/input/images/`，绝对路径原样使用；
文件不存在直接 `NotFoundError`，不静默跳过。

### 帧与幂等

白板帧输出在 `videos/<slug>/cards/whiteboard/`，已存在的帧跳过。改脚本后要强制
重渲，删掉该目录再跑 `compose run`。

音画同步以 **TTS 实测段时长**为准：`Σ 帧显示时长` 精确等于 `Σ 实测段时长`。

## 入口二：Markdown 文章直出

```bash
vagent whiteboard render ./article.md --only-stills   # 先复核版式（几秒）
vagent whiteboard render ./article.md                 # 整片（约 1 小时）
vagent whiteboard render ./article.md --fresh         # 改过文章后必须加
```

管线：

```
article.md
  → parseArticle()        分镜 + cast（谁说话）+ format 指令
  → speakSection()        Edge TTS 逐句合成（可多人）+ 词级时间戳 + 落盘缓存
  → resolveFormat()       按实测总时长定体裁：<3min 竖版短片 / ≥3min 横版长教程
  → composeStoryboard()   匹配素材 → 白板版式 → 时间轴（写/搬/擦/指 + 整板擦净）
  → renderFrames()        resvg 逐帧
  → buildNarrationTrack() 逐句 adelay 入轨 → mixSfx() 叠 writing/whoosh
  → muxVideo()            ffmpeg → mp4（+ 旁挂 SRT）
```

体裁按**实测配音总时长**判而非字数估算：同样字数，播报腔和快语速能差出小一半
时长，跨过 3 分钟这条线就会选错版式（竖版短片与横版长教程不是等比缩放关系）。

### 文章写法（也是 LLM 的输出约定）

| Markdown                      | 含义                                   |
| ----------------------------- | -------------------------------------- |
| `# 标题`                      | 全片主标题                             |
| `> cast: …`                   | 片级指令：角色 → 音色                  |
| `> format: auto\|short\|long` | 片级指令：强制体裁                     |
| `## 标题`                     | 一个分镜，标题写在板上                 |
| 普通段落                      | 口播台词（**只有它进配音**，板上不写） |
| `角色：台词`                  | 指定说话人（角色须在 `cast` 里）       |
| `角色（情绪）：台词`          | 指定说话人 + 情绪                      |
| `- 列表项`                    | 板上的打勾要点（写）                   |
| `~~文本~~`                    | 先写、再擦掉的假设（擦）               |
| `![alt](路径)`                | 搬进画面的外部图片（搬）               |
| `![alt](il:kw1,kw2)`          | 素材库英文检索词，匹配一张扁平插画     |
| `> background: grid`          | 片级指令：板面底纹（六种，见 §1）      |
| ` ```chart bar\|pie `         | 图表：柱状图 / 饼图（见「图表块」）    |
| ` ```table `                  | 表格（首行表头）                       |
| ` ```flow `                   | 流程图，支持分支与汇合（见下）         |
| ` ```mindmap `                | 思维导图（首行 = 中心主题）            |
| ` ```icons `                  | 图标流：`图标名 \| 标签`，箭头自动串联 |
| ` ```scene lecture `          | 场景组件（lecture/discussion/…）       |
| ` ```note cloud `             | 便签 / 云朵 / 对话框里的一句话         |
| ` ```status `                 | 状态徽章：`状态 \| 文字`               |
| `- 要点里的 ==高亮==`         | 荧光笔涂抹（黄）                       |
| `- 要点里的 **重点**`         | 文字下方强调线                         |
| `- 要点里的 ((圈出))`         | 手绘椭圆圈起来                         |

```
> cast: 主讲=news-male-formal, 提问=narrator-female-warm
> cast: interview          # 也可以直接写预设名
> format: auto
```

情绪词：`平静`/`沉稳`→calm，`上扬`/`轻快`→upbeat，`严肃`/`警告`→serious,
`温和`/`安慰`→gentle，`急`/`紧迫`→urgent，`设问`/`疑问`→question。

两条容易翻车的约定：

- **口播与板书故意分离。** 板上是关键词，口播是完整句子。让两者相同是最常见的
  翻车方式——观众会去读板上的长句，然后既没听清也没看完。
- **插画检索词用英文。** 素材库关键词是英文，中英映射属于上游 LLM 的活（它在读
  全文，比事后猜关键词准）。库里 2362 条，同片锁一种画风（默认 `Azureline`），
  五种画风线宽配色体系不同，混用会像拼贴。

### 图表块（`chart`）

板上画一张**带真实刻度和数值**的图表，跟着讲解逐根长出来：

````markdown
## 三种方案的年成本

主讲：先看钱。自建看起来最自由，但一年下来是三种方案里最贵的。

```chart bar 单位=万元
自建 92
托管 45
混合 61
```
````

块首行是 `chart <种类> [单位=…]`（`unit=` 亦可，全角等号也认），其后每行一条
`标签 数值`，分隔符用空白或 `|`（便于对齐着写）。种类支持 `bar`（柱状）和 `pie`（饼图）。

`pie` 的**百分比由渲染层算**，不要求作者写：作者给原始值（58 / 27 / 15），占比是
派生量。让作者自己算一遍等于同一份数据写两处，对不上时观众看到的是一张自相矛盾
的图。标签统一挂在饼外、用引线连过去——小于 15% 的扇区里放不下"类目 42%"，而
"小的放外面、大的放里面"的混排会让人每次重新找标签在哪。

**刻度交给 `d3-scale`**：最大值 92 时纵轴取 0/20/…/100，最高的柱子因此留出余量。
"该标 0/25/50/75/100 还是 0/20/40/60/80"有成熟算法（nice numbers），自己写会在
边界值上出 0/23/46/69/92 这种别扭刻度。

**排拍**：第一拍画坐标系（轴 + 刻度 + 单位，各刻度错开起笔而不是排队），之后
**每根柱子一拍**——柱框 → 填色 → 柱顶数值 → 轴下类目名。图表的教学价值来自"跟着
讲解逐步长出来"，一张完整的图直接出现和一张 PPT 截图没区别。

**布局**：与外部图片同规则——本段没有 `- 要点` 时占满内容宽度，有要点时留在媒体栏。
图表比插画更吃宽度（纵轴要放刻度值、横轴要放类目名），挤在窄栏里刻度会先糊掉，而
刻度糊掉的图表就退回装饰了。

**这些情况会当场报错，不静默降级**（超限不是缩字号能救的——刻度值小于可读下限，
图表就从"解释"退化成"装饰"）：

| 写法                      | 报错                              |
| ------------------------- | --------------------------------- |
| 数据 < 2 条或 > 6 条      | 要求 2–6 条，请把这一段拆成两段   |
| `托管很贵`（缺数值）      | 数据行读不懂（应为「标签 数值」） |
| `自建 -5`                 | 数值须为非负数                    |
| 类目名超过 6 字           | 类目名过长，并点名是哪几个        |
| 全部数值为 0              | 画不出可比较的图形                |
| 同段既有图表又有图片/插画 | 抢同一个媒体位，请拆成两段        |

非图表的围栏块（```js 之类）会被**跳过并告知到 stderr**——不朗读代码块，但也不
静默丢内容。

### 整片观感：一块被拖动的画布，不是一页页幻灯片

四条互相咬合的规则，目标是"一个人拿铅笔在一块大画板上边讲边画"：

1. **标题降权。** 标题只有 64px（横版）/ 76px（竖版），下划线细到 3.6px 且只划到标题
   宽度的 78%。早先横版是 104px 标题 + 6.5px 蓝线，画面读起来是"大标题 + 一点内容"；
   标题只是"这一块讲什么"的标签，主角是图。
2. **段与段之间画连接箭头**（`Storyboard.links`）。在"停一下"到平移之间画出来，笔把
   视线引向下一格，运镜因此有了动机。弧线而不是直线：直线连两个方块读作流程图的边，
   弧线读作顺手一带。这条箭头**不参与按格剔除**——它横跨两格，挂在任一格上都会在另一
   格单独可见时被剔掉。
3. **格子比画幅小、间距收紧**（格高 0.78 画幅高、横向留白 5%）。镜头视野因此比格子大，
   相邻内容会从画面边缘露出一角，这就是"同一块画布"的观感来源。留白给到 8% 以上时，
   平移中途有一段两边都空，那一瞬间就退回换页了。
4. **内容在格子里竖向居中**（补剩余高度的 42%，不是 50%）。一段内容通常只用到画幅上部
   六成，不居中的话收尾拉远时行与行之间连成大片空白。只补一半是因为标题应比几何中心
   略高，而且字幕压在画面下方 12% 处。

收尾仍是拉远看全景（`ZOOM_OUT_SEC` + `OVERVIEW_HOLD`）：加上连接箭头之后，全景读起来
是一条蛇形的讲述线索，而不是一堆并排的方块。

**格高小于画幅的代价，在 `contentBottom(L)` 里结账。** 镜头把一格居中放进画幅，段坐标
（格子局部坐标）因此整体下移 `(1-0.78)/2` 个画幅高——横版 119px。同时字幕带是画幅坐标
里的东西（底边 12% 画高，白底板 + 一行 46px 字）。两件事叠起来，能画的最低点是

```
contentBottom = min(格高 - 底边距/2, 字幕带顶 - 镜头位移)
```

横版算下来是 724px，而不是"画幅高 - marginBottom"的 988px。差出的这 260px 一开始没算，
表现是五分支导图的最后一个框正好被字幕压住——两项各错一点，恰好叠成一整个节点的高度。
所有媒体位（图片 / 插画 / 图表 / 板书块）和竖向居中都按这个值算。

### 板书块（表格 / 流程 / 导图 / 图标流 / 场景 / 便签 / 状态）

设计系统 2.0 的图形元素也走围栏块，和图表共用**同一个媒体位**（一段只能有一个：
图片 / 插画 / 图表 / 板书块，多写当场报错）。每种块都是**一串拍子**而不是一个元素：

| 块        | 块体格式                    | 排拍                                                               |
| --------- | --------------------------- | ------------------------------------------------------------------ |
| `table`   | 每行 `格 \| 格`（首行表头） | 先画整张网格，再**一行一拍**填字（同行的格错开 0.12s 起笔）        |
| `flow`    | 节点行 + 边行（见下）       | **一节点一拍**，入边归属该节点自己那一拍（先有"然后"，再有下一步） |
| `mindmap` | 首行中心，其余为分支        | 中心一拍，之后**一分支一拍**（弧 → 框 → 字）                       |
| `icons`   | 每行 `图标名 \| 标签`       | **一步一拍**（箭头 → 图标 → 标签）                                 |
| `scene`   | 首行可选一句说明            | 按 `ScenePart` 分组，**一组一拍**（板一拍、人一拍）                |
| `note`    | 恰好一行文字                | 容器一拍 + 文字一拍                                                |
| `status`  | 每行 `状态 \| 文字`         | **一条一拍**（徽章 → 文字）                                        |

参数：`note sticky|cloud|speech`（默认 sticky）、`scene lecture|discussion|presentation|thinking|success`、
`status` 的状态名为 `important|info|caution|success|error`。

两条随画幅走的版式规则，都是看渲图发现的：

- **场景按高度限宽**（`w ≤ h × 1.7`）再居中。场景构图假定框接近 3:2；横版内容宽是
  4.7:1，铺满会把板拉成一条横幅、人缩成一个火柴头。
- **图标流在窄框改纵向**（每步分到的宽度小于 5 倍正文字号时）：竖版横排四步，每步
  只有 270px、图标缩到 150px，而下方还空着一大片；纵向排图标能大一倍，标签写右边。

#### 流程图的分支与汇合

两种行混用（旧的纯链式写法完全兼容）：

```
估算成本                       ← 节点行：相邻节点行自动串成一条链
预算够吗？                      ← `？`结尾 = 判断（菱形）
预算够吗？ -[够]-> 定方案        ← 边行：`源 -> 目标`，`-[条件]->` 带分支标签
预算够吗？ -[不够]-> 砍范围
定方案 -> 上线                  ← 两条边指向同一段文本 = 汇合
砍范围 -> 上线
```

节点按**文本**引用，写没出现过的文本就是新建节点，所以汇合不需要额外语法。布局交给
**dagre**（Sugiyama 分层法）：分层、同层排序、连线绕行都有成熟算法，自己排会在"两条
分支汇合"这个最常见的形状上出交叉线。起止形状按**图结构**判断（没有入边或没有出边的
画成圆角矩形），不按第一行/最后一行——有分支之后，最后一行往往是一条汇合边。

拍子顺序取 dagre 的拓扑序，和人讲流程的顺序一致：先把主干走通，再回来讲另一条分支。
上游还没讲到的那条入边**留到最后一拍**才补（标签跟着一起写——"不合格就退回去"的条件
全在那个词上），否则画面上会出现一根从空白连过来的箭头。

**生长方向跟着框的形状走**：框宽 ≥ 1.5 倍框高时朝右（`rankdir: LR`），否则朝下。横版
满宽的框是 3:1 以上的横条，四步朝下排会挤成一列窄条——节点缩到只剩字高，左右各空一大
片；朝右排同样四步能放大一倍多。同层节点还要 `align` 对齐，否则回头边生成的虚拟节点会
把链上的节点一个个往下顶，直链画出来是波浪形的。

`flow`/`mindmap`/`scene` 拿 52% 画高，其余拿 34%——前三者是纵向生长或整幅构图，给
不够高就会被压扁；表格、图标流、状态是横向铺开的，给太多高度只会留白。

校验一律 fail-loud：行列数上限（表格 5 行 4 列）、节点数 2–5、单格 8 字、图标流标签
6 字、便签 16 字，以及图标名 / 场景名 / 状态名的白名单（写错名字会报出可用清单）。

### 要点里的行内标记

`==高亮==`（黄色荧光笔）、`**重点**`（下方强调线）、`((圈出))`（手绘椭圆）只在
`- 要点`行里生效。普通段落是口播台词，在台词里写画面指令只会让 TTS 把符号念出来。

三种标记都在**整行写完之后**才补上：真人是先写完一句再回头涂色/划线/圈起来，而且
涂抹宽度要等这行字最终有多宽才知道。不支持嵌套（`==**字**==` 报错）——涂色和划线
叠在同一段字上，画面读不出强调的是哪一个。

### 画笔光标

默认 `--cursor hand`：手拿笔，参考 `assets/design/横屏手比例.png` 与 `竖屏手比例.jpeg`
——两张参考里都只看得见**手掌 + 小臂**，前臂被画幅边缘齐齐切掉，既没有渐尖收笔也
没有袖口。

手臂收尾按画幅分派，是被**量出来**的，不是偏好：

| 画幅           | 臂高（= 素材归一高度）      | 手宽                | 收尾                 | 为什么                                                                                                                   |
| -------------- | --------------------------- | ------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 横版 1920×1080 | `LANDSCAPE_ARM_HEIGHT` 1550 | 818px（43% 画宽）   | `extend`             | 手放大后真手臂本身就伸到画幅外，补的带子整段落在画外、看不见                                                             |
| 竖版 1080×1920 | `PORTRAIT_ARM_HEIGHT` 2250  | 1187px（110% 画宽） | `none`（什么都不补） | 臂高已经超过画幅高，素材自己那段前臂就出画了，不需要补；补的话那条又粗又长的合成色带一定读作假的（纯色、横向渐变都试过） |

取值判据是**最坏帧**：全片笔尖最高的那一帧（通常是写标题第一个字），此时贴图底边
（= `笔尖y − tipY + 臂高`）必须落在画幅之外。最坏帧不能靠 `marginTop` 估——标题也是
手写出来的，所以要实测：

```bash
bun run experiments/hand-frame.ts long 16.05 /tmp/worst.png   # 在任意时刻渲单帧
```

示例文章上最高笔尖是横版 y=126、竖版 y=210，对应余量 502px / 404px。余量留得宽是因为
"刚好够"的失效表现最难看：画板中间会多出一截斜切的断臂（竖版 1830 那一档实测就是断口
正好露在底边内侧），比手大一点难看得多。

书写素材由 `HAND_WRITE_SLUG` 钉死为 `matt-pencil-1`（422×800，比例 0.527），不交给
`pickGesture` 按"哪支笔像白板笔"自选：手宽 = 臂高 × 素材宽高比，chalk-1（0.750）在
竖版会算出 1.7 倍画宽的手。找不到这个 slug 时回退到该 persona 手臂最窄的一张。

素材侧的限制：三个 persona（suneeta / matt / hannah）的手臂都是**裸前臂、渐尖收笔**，
没有任何一个自带袖子；而参考图的手臂更长更窄（臂长:手宽 ≈ 1.81，我们的素材是 1.45），
这个比例差就是竖版补不出来的根因。真要复现参考图的竖版观感，需要补一张"手掌 + 短
小臂"的素材（授权须可追溯）。

`armExtensionSvg` 的两处修正：延长带画在贴图**之后**（盖住渐尖那段，silhouette 才是
等宽手臂），并加一道横向三段渐变（肢体是圆柱，两侧暗中间亮；纯色会读作一张纸）。

`--cursor pen` 换成只有一支笔（`assets/sparkol/pens/black-biro`），没有手。

`pens` 组本来就被 `listGestures` 排除在默认清单之外（它拿不出 erase/carry/point
三种手势，混进去会让"挑不到某个角色就退回全库"的逻辑拿一支笔去当橡皮），所以
只有笔的模式要显式 `includePens` + `writeOnly` 打开，并用 `armMode: "none"`
关掉袖口与假手臂——笔身下方是投影而不是前臂，套袖口会在投影上长出一块色块。

笔按 `PEN_DISPLAY_HEIGHT`（220）归一，不能沿用 `ARM_DISPLAY_HEIGHT`：后者是按
"手 + 前臂"768×1210 定的，拿去套 555×445 的斜放笔身会把一支笔放大到半个画面。

`--cursor hand` 回到手 + 前臂；此时手臂收尾按画幅朝向自动选（横版 `extend`
接出画面，竖版 `none` 不补、靠素材自己出画），`--arm` 可显式覆盖。

### 素材依赖与降级

| 缺什么                     | 表现                                                   |
| -------------------------- | ------------------------------------------------------ |
| 手写字体                   | 回退楷体笔画轮廓                                       |
| `assets/sparkol/`          | 无手势贴图（笔迹仍在）                                 |
| `assets/manypixels/`       | 退化为纯文字版式                                       |
| `assets/sfx/manifest.json` | 纯口播，不报错                                         |
| 文章引用的外部图片         | **报警到 stderr**（搬入 + 点指手势会缺失），不静默跳过 |

恢复素材见 [assets-setup.md](assets-setup.md)。

### 性能陷阱：不要给 resvg 传 `resourcesDir`

按相对路径引用手势 PNG 需要 resvg 的 `resourcesDir`，而这个选项让每帧慢一个
数量级（1080×1920 单帧实测 75ms → 608ms，开盘写更是 1396ms）。一段 20s 竖版
片子会从 45s 变成 6 分钟以上。

`hand.ts` 改为把手势贴图 inline 成 base64 data URI，并在加载时一次性降采样到
屏幕尺寸——inline 原始 800×1250 会让每帧 SVG 涨到 MB 级，逼 resvg 每秒重解码
30 次大图。切换后实测 62ms/帧（竖版）、75ms/帧（横版）。

### 笔尖位置来自像素，不是元数据

Sparkol 元数据的 `drawOffset`/`moveOffset` **不落在笔尖上**（实测偏移
20-60px，`suneeta-black-marker` 声明的 `(57,-16)` 甚至在图外，真实笔尖在
`(43,114)`）。`hand.ts` 从 alpha 通道量笔尖，只用元数据判断**笔指向哪个角**
（库里有左手套装）。元数据贡献它对的那部分（朝向），像素贡献精度。

注意 `pens/` 分组带投影，投影会碰到图角——同一套量法不能用在它上面。

### 收尾署名与关注引导

配了人设（`assets/persona/ermu.json`，见 `core/persona`）时，收尾拉远的过程中会在
画布右下角**手写笔名 + 一行 CTA**，并配一声 `sparkle`。文章级开关 `> signature: on|off`
（默认 on），没有人设文件时自动跳过、不报错。

三个位置决定它好不好看，都是渲图看出来的：

1. **落笔时刻 = 拉远过半**（`zoomOutFrom + ZOOM_OUT_SEC * 0.55`）。手写字是按笔画揭示
   的，签名 + CTA 要两秒左右；等拉远结束再落笔，成片结尾会把 CTA 截掉半句。同时
   `totalSec` 取 `max(原时长, CTA 写完 + 0.5s)`——全景停留时长是给观众扫图的，不该顺带
   决定签名能不能写完。
2. **位置 = 最后一格的内容之下**，不是全景外接矩形的右下角。一段内容只用到格子上部约
   七成（见 `CELL_H_RATIO` 与 `contentBottom`），格底那条留白是全景里唯一确定空着的
   地方；按 bounds 右下角算会压到最后一段的图（实测压在云朵便签上）。
3. **字号按 `bounds.w` 取**（2.4%），不按画幅字阶取。签名只在拉远之后出现，那时整块
   画布缩到一屏（12 段的片子缩到约 0.18），画幅字阶的 64px 落到屏幕上只剩 12px。
   右对齐要按 `textWidth` 实测——CTA 是可配文案，按字号留位会把它推出画面右边缘。

## 音效

六个挂钩，每个都对应画面上**看得见的一件事**；语义由排版层声明
（`Storyboard.sfxCues`），混音层只按表铺声，不猜。

| id          | 触发                                    | 来源                       |
| ----------- | --------------------------------------- | -------------------------- |
| `writing`   | 笔真的在板上（相邻区间合并后铺垫）      | `penActiveSpans`           |
| `whoosh`    | 每次镜头移动（段间平移）                | `camMoves`（剔掉收尾拉远） |
| `pop`       | 图形块 / 图表 / 图片入场                | 媒体位那一拍               |
| `ding`      | 要点打勾逐条确认                        | 要点那一拍                 |
| `sparkle`   | 强调标记（划掉、口播问号/感叹号、署名） | 对应拍子 + 署名时刻        |
| `page-turn` | 收尾拉远看全景                          | `zoomOutFrom`              |

音量按类目分档（ding 0.2 / pop 0.14 / sparkle 0.18 / page 0.26，都低于 whoosh 0.32）：
点位多的类目叠起来会盖住口播。清单缺失或某一类缺素材 → 那一类静默跳过，纯口播也是
完整成片。

**一个静默失效的教训**：`whoosh` 原来挂在"擦板起点"，无限画布改版把擦板换成了镜头
平移之后，`wipe` 恒为 `null`，整片一声 whoosh 都没有，而日志、测试、契约全是绿的。
所以现在语义由产生它的那一层声明，而不是让混音层从元素列表里找线索。
