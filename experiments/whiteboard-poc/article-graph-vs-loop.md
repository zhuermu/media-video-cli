# 图工程 vs 循环工程

> cast: 主讲=narrator-male-steady, 提问=narrator-female-warm
> format: long
> background: grid

## 循环死了？

主讲：七月十八号，OpenClaw 的作者在推上问了一句：我们还在聊循环，还是已经转向图了。第二天，"循环工程已死，图工程当立"就传遍了时间线。

提问（设问）：那到底是范式换了，还是只是换了个说法？

主讲：这条片子做的就是这场审计。

```note speech
循环工程已死
```

## 两个词各指什么

主讲：先把定义摆清楚，两个词其实分得很干净。循环工程设计的是一个智能体自己转的那个圈：发现、计划、执行、验证，直到满足停止条件。

主讲：图工程是另一个层级的事——一个循环不够用了，你把多个专职节点连成一张有向图，状态沿着边流动。

```table
维度 | 循环工程 | 图工程
单元 | 一个循环 | 节点加边
你设计 | 停止条件 | 拓扑和路由
失效于 | 验证器弱 | 拓扑错了
```

## 循环长什么样

主讲：循环的形状是一个回头箭头。四步走完，验证没过就回到开头再来一遍，过了就交付。

主讲：注意这里只有一个上下文、一套提示词。整条工程学的重心，落在最后那个"验证"上——瓶颈从来不是模型，是你的验证器。

```flow
发现
计划
执行
验证
验证 -[没过]-> 发现
```

## 一个循环撑不住时

主讲：拿一个真实任务试试：每天早上读几个来源，写一页摘要，核对准确性再进你的收件箱。

主讲：写成一个大循环，一个智能体在同一个上下文里搜索、堆原始网页、起草、然后"审"自己刚写的稿。三个毛病同时冒出来。

```status
error | 上下文成泥潭
error | 自己审自己
caution | 来源只能顺着读
```

## 同一个任务，拆成图

主讲：换成三个节点。研究员并行铺开所有来源，只回结构化笔记，绝不写行文；写作者只看干净笔记，看不到原始网页；审稿人在一个全新的上下文里，只看稿子和验收标准。

提问：不合格呢？

主讲：路由回写作者。是新的眼睛在审，不是写它的那双眼睛。

```flow
研究员
写作者
审稿人
审稿人 -[不合格]-> 写作者
```

## 真正新增的三件事

主讲：把这个例子一般化，图真正买到的能力就三样：每个节点有自己的提示词、工具和干净上下文；控制流是你提前定义好的、能当图读的；还有单个循环做不到的那一步——分发到 N 条分支并行，跑完再汇合。

主讲：前两样是质量，第三样是形状上的新能力。

```icons
team | 专职分工
flow | 分发再汇合
magnifier | 路径可审计
```

## 代价也得说清

主讲：诚实的另一半是账单，而那个大循环没收你这笔钱。三套提示词要维护；节点之间要定状态契约——研究员到底交给写作者什么字段；还有一批全新的失效模式：汇合时悄悄漏掉一个来源、路由 bug 导致死循环、状态从一个节点漏进下一个。

主讲：每天跑的任务，这笔开销换来的是真实质量；只跑一次的任务，它就是纯税。

- ==三套==提示词要维护
- 节点间要有 **状态契约**
- 漏来源、死路由、((串状态))

## 是新范式还是新名字

主讲：现在说那个不客气但公道的读法。这个词是新的，这个做法不是。

~~图编排是刚发明的新玩法~~

主讲：状态机和图编排早就在跑了。LangGraph 用 add_node、add_edge 建 StateGraph，状态沿边传递；AutoGen 的 GraphFlow 支持顺序、并行、条件和循环；Google ADK 有图工作流、路由和跨系统委派。它们全都早于这个词。

- LangGraph 的 **StateGraph**
- AutoGen 的 GraphFlow
- Google ADK 加 ==A2A==

## 四问自检

主讲：所以在你告诉自己"我们从循环升级到图了"之前，先过这四问。

提问：数一下有几个"是"。

主讲：上下文真的拆开成专职的了吗？有没有真正的并行加汇合，而不是一串你画成方块的顺序步骤？路由能不能当图读，是提前定义的还是涌现出来的？还有最关键的一问——目标和验收标准，变了吗？

- 上下文拆开了吗
- 有并行加汇合吗
- 路由能当图读吗
- **验收标准**变了吗

## 数几个是

主讲：零到一个是，你手上是一个披着图的循环，那就留着它做循环，省下那一堆失效模式。两到三个是，你在真正地把循环组合成图，新能力开始抵得上它的成本。四个都是，那是活儿逼着你换的，不是时间线。

```status
error | 零到一：还是循环
caution | 二到三：在组合
success | 四个是：换范式了
```

## 图是第五层

主讲：把它放回坐标系里就不容易吵起来了。一个 AI 应用有五层，从模型往外一层层包：提示词、上下文、骨架、循环、图。图是最外那层，它包住下面的层，不替换它们。

主讲：所以循环不会被淘汰——图里的每个节点，本身就是一个循环。

```mindmap
五层
提示词
上下文
骨架
循环
图
```

## 带走这一句

主讲：图工程既是真的，也被过度营销了，这两句同时成立。真正新的是并行专职节点、分发汇合和可审计的控制流；被重新包装的是那个词本身。

主讲：留下来的框架其实很朴素：循环是图里的一个节点。你不是从循环毕业到图，而是在一个循环真的不够用的时候，才把循环组合成图。

```note cloud
先把循环做对
```
