# 白板讲解视频

一篇 Markdown → 一条带手写板书、AI 配音、手势动作和字幕的 mp4。

**仓库**：`/Users/xiaowely/ws/git/shortcut/media-video-cli`
**库**：`src/core/whiteboard-video/`（入口 `renderWhiteboardVideo`）
**CLI**：`bun run src/cli/main.ts whiteboard render <article.md>`

## 什么时候用

用：技术方案讲解、踩坑复盘、概念科普、流程说明、组内分享 —— 凡是"有人一边讲一边在白板上写"讲得更清楚的内容。

不用：需要真人出镜、需要屏幕录制演示操作、内容主体是表格或代码大段（白板写不下，会挤成一团）。

## 四步（每一步都不能跳）

```bash
cd /Users/xiaowely/ws/git/shortcut/media-video-cli
vagent() { bun run src/cli/main.ts "$@"; }

# 0. 参数从 schema 拿，不要从本文抄
vagent schema --json      # whiteboard render 的全部 flag：值域、默认值、产物

# 1. 写脚本（见下面「脚本约定」）；产物默认落在脚本所在目录的 out/ 下

# 2. 试跑：校验脚本语法 + 报段数/帧数/预计耗时，零写入
vagent whiteboard render path/to/article.md --dry-run --json

# 3. 出关键帧目视复核版式（几秒）
vagent whiteboard render path/to/article.md --only-stills

# 4. 试看前 40 秒，听配音 + 音效 + 看字幕（约一分钟渲完）
vagent whiteboard render path/to/article.md --preview 40 --fresh

# 5. 渲整片（9 分钟的片子约 1 小时）
vagent whiteboard render path/to/article.md
```

**为什么要有第 2 和第 4 步。** 第 2 步在一秒内查出脚本语法错（图形块写错、超限、
一段配了两个媒体块）——这些错在真跑时要等到讲到那一段才炸。第 4 步是唯一能判断
"配音音色对不对、音效吵不吵、字幕认不认得出"的手段，而这三件事听一遍就知道，
渲完整片再发现要重来一小时。产物带 `-preview` 后缀、帧目录也分开，不会污染整片续跑。

**第 3 步不能跳过。** 整片渲染近一小时，版式问题（图太小、要点溢出画面、标题撞图）只有看到画面才发现。`--only-stills` 每段出一张"讲到一半"、每次转场出一张"擦到一半"，是唯一能在分钟内判断版式对不对的手段。看图时注意：要点有没有超出画面、图里的字看不看得清、标题有没有和内容重叠。

改完脚本重渲**必须加 `--fresh`**，否则会复用旧帧混进新片（默认续跑是为了中断后接着渲，不是为了改稿）。

## 脚本约定

```markdown
# 全片主标题

> cast: 主讲=narrator-female-warm, 提问=narrator-male-lively
> format: auto

## 第一段的板上标题

主讲：这一段的口播台词。完整句子，观众听的是这个。

提问（设问）：需要设问的时候换个人问，观众立刻知道这是问题不是结论。

主讲（严肃）：这里有个坑 —— 情绪写在角色后面的括号里。

![素材](il:authentication,security,login)

- 板上写的要点
- 每条一句话，不超过十个字
```

| 写法                                | 效果                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------- |
| `# 标题`                            | 全片主标题（长横版会进页眉）                                              |
| `## 标题`                           | 一个分镜（一屏），标题手写在板上                                          |
| 普通段落                            | **口播台词**（只有它进配音，板上不写）                                    |
| `角色：台词`                        | 指定说话人（角色必须在 `cast` 里，否则报错）                              |
| `角色（情绪）：台词`                | 说话人 + 情绪                                                             |
| `- 列表项`                          | 板上的打勾要点（一条一"拍"，逐条写出来）                                  |
| `~~文本~~`                          | 先写下来、再用板擦擦掉的假设                                              |
| `![](本地路径.png)`                 | 手托着从画面外搬进来的外部图片                                            |
| `![](il:kw1,kw2)`                   | 素材库检索词（**必须英文**），自动匹配一张插画                            |
| ` ```chart bar ` / ` ```chart pie ` | 柱状图 / 饼图，带真实刻度与数值（见「图表」）                             |
| ` ```table `                        | 表格，每行 `格 \| 格`，首行是表头                                         |
| ` ```flow `                         | 流程图；节点行自动串链，`？`结尾是判断，`A -[够]-> B` 写分支与汇合        |
| ` ```mindmap `                      | 思维导图，首行是中心主题                                                  |
| ` ```icons `                        | 图标流，每行 `图标名 \| 标签`，自动用箭头串起来                           |
| ` ```scene lecture `                | 场景组件（lecture/discussion/presentation/thinking/success）              |
| ` ```note cloud `                   | 一句话装进便签/云朵/对话框（sticky\|cloud\|speech）                       |
| ` ```status `                       | 状态徽章，每行 `状态 \| 文字`（important\|info\|caution\|success\|error） |
| `> background: grid`                | 板面底纹（plain\|grid\|lined\|cream\|texture\|dots）                      |
| `- 要点 ==高亮==`                   | 要点里的黄色荧光笔涂抹                                                    |
| `- 要点 **重点**`                   | 要点里的文字加强调线                                                      |
| `- 要点 ((圈出))`                   | 要点里的手绘圈图                                                          |

情绪词：`平静/沉稳` `轻快/上扬` `严肃/警告` `温和/安慰` `急/紧迫` `设问/疑问`。

### 三条硬约束

**口播和板书必须不一样。** 板上写关键词，口播说完整句子。写成一样是最常见的翻车方式：观众会去读板上的长句，结果既没听清也没看完。

**要点每段不超过 5 条，每条不超过 10 个字。** 超了会写到画面外 —— 版式不会自动缩，因为缩小字号在投屏上就看不见了。

**插画检索词写英文。** 素材库（`assets/manypixels/`，2362 条）的关键词是英文。中译英是你的活，你在读全文，比事后猜关键词准。给 2–4 个词，命中的是分最高那条；匹配不到就退化成纯文字，不会报错 —— 所以要看 stderr 里的"素材匹配"日志确认配到了什么。

### 图片布局规则

**这一段没有 `- 要点` 时，图占满内容宽度；有要点时图挤在媒体栏。**

架构图、决策流程图这类宽高比 2:1 以上、图里有小字的图，塞进右栏只有 380px 高，投屏上根本看不清。要让这类图看得清，就把那一段写成"只有口播 + 图，没有要点"。规则挂在"有没有要点"上是故意的：作者能预期，不会静默丢内容。

## 人设、术语、改写协议

写脚本之前先读人设：

```bash
vagent persona show --json
```

- **口播按 `tone` 写**：先给结论、给可复现的数字或命令、不用「颠覆」「必看」这类词、
  有代价就说代价。
- **`keepEnglish` 里的术语保留英文**（prompt / context / harness / loop / graph /
  agent / verifier / fan-out / fan-in / state / topology / routing / embedding /
  token / RAG / MCP / skill / context window / state machine / guardrail）。板上写、
  口播念都保留原词：这些是社区共识的检索锚点，译名会把精确的词变含糊，而且不同文章的
  译法还不一致。首次出现可以加一句中文注解。
- **改写海外英文原文**时：术语不译；原文的「某人认为」不能升级成「事实是」；数字、
  版本号、时间点回原文核对；保留作者与出处（口播里点名是谁说的）；按观众的问题顺序
  重排结构，而不是逐段翻译。
- **禁区**看 `avoid`（财经投资 / 医疗健康 / 法律 / 赌博）。硬红线是 CLI 的
  domain-guard 词表，命中直接报错且零产物。

## 板面默认是深色

不写 `> background:` 就是深色网格板（`dark-grid`）。短视频平台的标题、时长、按钮是
**白字**，白板会把它们吞掉，观众连视频多长都看不到。

- 想要白板：`> background: grid`（或临时 `--background grid`）。
- 深色一旦生效，墨色、注解色、强调色、字幕、荧光笔**整套跟着翻**，脚本不用管。
- 插画（`![](il:...)`）多数是浅色系的，在深板上像"贴了张纸"，正常。

## 片头封面

默认会生成一张封面并**拼成成片的第一帧**（定格 2.5s），同一张也单独落盘成
`out/<tag>-cover.png`，可以直接交给发布包当平台封面。

```markdown
> cover: 7 # 主视觉取第 7 段的图形块（on/auto = 第一个有块的段，off = 不做）
> subtitle: 一句副标（没写就不画那一行）
> tagline: 一句金句（缺省时用片尾最后一个 note 块的文本）
```

写脚本时的两条建议：

- **`> cover:` 指定那段最能代表全片的图**，别依赖 auto。auto 取第一个有块的段，
  而第一段常常是个钩子便签，信息量不如中段那张对比图或流程图。
- **主标题（`#`）要短**。封面标题一行放不下时会自动收字号，收到很小就没意义了；
  长句放 `> subtitle:`。

## 收尾署名

配了人设时，收尾拉远看全景的同时会在画布右下角**手写笔名 + 一行关注引导**
（`signature` 与 `cta[0]`），并配一声 sparkle 音效。

- 不想要就在文章里写 `> signature: off`（默认 on）。
- 没有人设文件时自动不署名，不报错。
- 主讲音色默认取人设的 `defaultVoice`（沉稳男声）；文章里显式写了 `> cast:` 以文章为准。

## 音色

`> cast:` 可以直接写预设名，也可以逐个指定 `角色=音色id`。

| 预设                       | 组成                             | 用在                 |
| -------------------------- | -------------------------------- | -------------------- |
| `solo`                     | 旁白=沉稳男声                    | 单人片，默认         |
| `interview-female`         | 主讲=清亮女声 + 提问=年轻男声    | **长教程默认用这套** |
| `interview`                | 主讲=播音男声 + 提问=温暖女声    | 正式发布、对外宣讲   |
| `duo` / `class` / `banter` | 见 `voices.ts` 的 `CAST_PRESETS` | 竖版轻内容           |

常用音色 id：`narrator-female-warm`（清亮标准女声，最好懂）、`narrator-male-steady`（沉稳男声）、`news-male-formal`（播音腔男声）、`narrator-male-lively`（年轻男声）、`narrator-female-lively`（外放女声）。全部 14 条见 `voices.ts` 的 `VOICE_LIBRARY`，每条带适用场景。

**两个坑：**

1. **深音色 + 大量 `严肃` 会发闷。** `严肃` 会放慢、压低、提音量；本来就低的男声（播音腔）连着几段之后字咬不清，尤其在手机小喇叭上。长教程如果坑很多，主讲用清亮女声（`interview-female`）。
2. **免费 TTS 通道不支持 Azure 情绪标签。** 情绪是靠"选音色 + 调韵律"近似的，幅度刻意小 —— 语速超 ±12%、音高超 ±3 半音就有电子音。真要精细情绪得换付费后端。

一条视频出现两个声音不是为了花哨：讲解片里"提问"和"回答"用同一个声音，观众分不清那句是设问还是结论。换个声音提问，等于免费得到一层结构。

### 图表（真实刻度与数值）

要讲"量"的时候用图表，不要用嘴报数字：

````markdown
## 三种方案的年成本

主讲：自建看起来最自由，但一年下来是三种里最贵的。

```chart bar 单位=万元
自建 92
托管 45
混合 61
```
````

首行 `chart bar [单位=…]`，其后每行 `标签 数值`（空白或 `|` 分隔）。刻度由 d3-scale
自动取整（92 → 纵轴到 100），柱子跟着讲解**一根根升起来**，柱顶标数值、轴下标类目。

`chart pie` 一样只写原始值，**百分比由渲染层算**（别自己算，写两处会对不上）。

### 图形块（表格 / 流程 / 导图 / 图标流 / 场景 / 便签 / 状态）

和图表共用同一个媒体位：**一段只能有一个**（图片 / 插画 / 图表 / 图形块），多写会报错。

````markdown
## 决策要走的流程

主讲：选型不是拍脑袋，它有固定几步。

```flow
估算成本
预算够吗？
预算够吗？ -[够]-> 定方案
预算够吗？ -[不够]-> 砍范围
定方案 -> 上线
砍范围 -> 上线
```

```icons
question | 问题提出
magnifier | 分析过程
lightbulb | 解决方案
trophy | 最终效果
```

## 落地前的检查项

```status
success | 预算已批
caution | 人力待补
```
````

每种块都跟着讲解**逐步长出来**（表格一行一拍、流程一节点一拍、状态一条一拍），
不会整张图一次出现。

限额（超了当场报错，不会自动缩）：表格 5 行 4 列、单格 8 字；流程/导图/图标流
2–5 个节点、节点 8 字、图标标签 6 字；便签一行 16 字；状态 4 条、每条 12 字。
图标名要在图标库里（question / magnifier / lightbulb / trophy / star / team / …），
写错会报出可用清单。

竖版里图标流会自动**改成纵向排**（图标在左、标签在右），横排四步在 1080 宽里太小。

硬约束（写错会**当场报错**，不会渲完才发现）：

- 数据 **2–6 条**。超了拆段——刻度值缩到读不清，图表就退化成装饰了。
- 类目名 **≤6 字**；数值必须是**非负数**；不能全为 0。
- **一段只能一张图**，且**不能和 `![]()` 图片/插画同段**（抢同一个媒体位）。
- 想让图占满宽度就**别给这一段写 `- 要点`**（同图片规则）。图表比插画吃宽度，
  挤在窄栏里刻度先糊。

目前只支持 `bar`。非图表的围栏块（` ```js ` 之类）会被跳过并在 stderr 告知——
白板视频不朗读代码块。

## 画笔光标

**默认是手拿笔**（`--cursor hand`）。关键是手放得**足够大**：手小了，那条渐尖收笔
的前臂会断在画板中间，很假；放大到手臂直接伸出画幅之外就没这个问题了——这块画板
可以理解成一块 iPad 画布，手搭在上面、手臂在屏幕外。横版因此走 `extend`（不套袖口）
且用大一号的手；竖版画幅 1920 高，手臂接不出去，仍在手腕套袖口。

`--cursor pen` 换成只有一支笔（银灰细杆，Apple Pencil 观感），适合不想有人手出现
的场合；代价是没有擦除/搬运/点指三种手势贴图。

## 手势

四类手势按脚本内容自动选，不用手动指定：

| 角色  | 触发        | 语义                               |
| ----- | ----------- | ---------------------------------- |
| write | 有文字/要点 | 握笔写，笔尖压在正在出现的那一笔上 |
| carry | `![](图片)` | 手托着图从画面外搬进来             |
| erase | `~~文本~~`  | 板擦擦掉                           |
| point | 搬进来的图  | 点两下 + 光环，强调                |

`--persona <名>` 换人（`assets/sparkol/` 下的目录名，如 `suneeta` / `matt`）。笔的颜色按墨色自动挑（marker > sharpie > brush > chalk > …）。

**手臂按画幅收尾**（自动，不用管）：素材里的手臂是画到一半就渐尖收笔的，直接用会在画面正中间断掉。

- **横版**顺着手臂方向接一段出画面 —— 画幅只有 1080 高，手臂本来就快到边了。
- **竖版**在手腕切断、套一个袖口 —— 画幅 1920 高，接手臂要接 1500px，那条又粗又长的色带会横穿半个画面。

段间转场是**整板擦净**，不是硬切：白板上的东西是一笔一笔画上去的，凭空消失不符合这个世界的规则。

## 体裁

`> format:` 三个值：

- `auto`（默认）：按**实测配音总时长**判，< 3 分钟出竖版，≥ 3 分钟出横版
- `short`：1080×1920 竖版短片，单栏纵向流，无页眉
- `long`：1920×1080 横版长教程，双栏（左文右图）+ 页眉（标题 / `02 / 14` / 进度条）

用实测时长而不是字数估算：同样字数，播报腔和快语速能差出小一半时长，跨过 3 分钟那条线就会选错版式 —— 而两套版式不是等比缩放关系。

想强制：`--kind short|long|auto`（覆盖脚本里的 `format`）。

## 参数

**别在这里查参数**——`vagent schema --json` 里 `whiteboard render` 那一条带全部 flag 的
类型、值域、默认值、示例与产物清单，而且命令改了它自动跟着改。这里只记四个最常用的
判断：`--dry-run` 试跑、`--only-stills` 复核版式、`--preview <秒>` 试听、改稿重渲必须
`--fresh`。

产物：`out/<tag>.mp4` + `out/<tag>.srt`（软字幕，硬字幕已烧进画面）。

## 排查

| 现象                       | 原因                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| `帧序列不完整：缺 N 帧`    | 帧目录被别的进程清过。**重跑同一条命令即可补齐**（默认续跑）           |
| 某段没有插画               | 检索词没命中。看 stderr 的"素材匹配"日志，换英文词再试                 |
| `![](路径)` 报路径解析失败 | 图片路径相对**脚本文件所在目录**解析，不是 cwd                         |
| 要点写到画面外             | 那一段要点太多或太长。拆成两段                                         |
| 图里的字看不清             | 把那段的 `- 要点` 删掉，图就会占满宽度                                 |
| `角色 "X" 不在 cast 表里`  | `> cast:` 里漏了这个角色                                               |
| 配音很慢                   | 首次合成要走网络；结果落盘缓存在 `<脚本目录>/cache/tts/`，重渲不再合成 |

**并行渲两条视频是安全的**：帧目录和产物名默认都按脚本文件名派生。但**不要给两条视频传同一个 `--frames` 或 `--tag`**。

## 内部约定（改代码时才需要知道）

- 帧渲染器一律 `loadSystemFonts: false`，`<text>` 会渲成空白 —— **任何文字必须走矢量路径**（`vectorText` / `markerTextEl`）。
- 不给 resvg 传 `resourcesDir`（实测每帧 75ms → 608ms），图片必须内联 data URI 且在装载期缩到显示尺寸。
- 单段时长 = `max(配音, 板面)`，**不缩放笔速**：书写速度是感知常量，忽快忽慢观众立刻觉得在赶时间。
- 本机 ffmpeg 没编 libass / freetype，所以字幕是画进帧里的，不是 `-vf subtitles`。
